# Cloning from gitolite
gitolite is behind the doc firewall, and so we need to use Proxy Jump to get to it.
1. Rewrite the SSH Url to the gitolite one, by replacing the start with gitolite@gitolite.doc.ic.ac.uk. E.g. git@gitlab.doc.ic.ac.uk:lab2526_spring/70010_DL_CW_2_kss22.git becomes gitolite@gitolite.doc.ic.ac.uk:lab2526_spring/70010_DL_CW_2_kss22.git
2. Clone by proxyjumping through sftp.doc.ic.ac.uk

Keys wise:
1. For the gitlab clone, use the key from IMPERIAL_GITLAB_SSH_KEY
2. For the gitolite clone, access sftp.doc.ic.ac.uk using IMPERIAL_DOC_SSH_KEY and the username IMPERIAL_USERNAME (see the python file, this is already an option the user has to provide for labts), and then use the key from IMPERIAL_GITLAB_SSH_KEY to access gitolite.

If this were an SSH config, it would look like this:

```
Host sftp.doc.ic.ac.uk
	User ${IMPERIAL_USERNAME} # filled in as needed
	HostName shell5.doc.ic.ac.uk
	IdentityFile ${IMPERIAL_DOC_SSH_KEY} # filled in as needed
Host gitolite.doc.ic.ac.uk
  HostName gitolite.doc.ic.ac.uk
  IdentityFile ${IMPERIAL_GITLAB_SSH_KEY} # filled in as needed
  ProxyJump sftp.doc.ic.ac.uk
```

You must not alter the user's SSH config file, but you can use the above as a reference for how to set up the SSH connection. If you can not find a way to do the clone without modifying the user's SSH config file, please let me know and we can discuss alternatives. Note that my computer already has the above in my SSH config file, but this tool might be used by users who haven't set up their SSH config file like that (but they will have the SSH keys).
